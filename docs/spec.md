# 仕様メモ

## 目的

日本株の銘柄コードを入力し、最新の決算短信・決算関連資料を探して、スマホで読みやすい標準ルール分析レポートを生成する。

## 方針

- 有料APIは使わない。
- 外部LLM APIは使わない。
- 投資助言、売買推奨、価格目標、将来株価の予測は出さない。
- TDnet公開閲覧ページとJPX「東証上場会社情報サービス」はベストエフォート取得とする。
- 失敗時は手動PDFアップロードまたはPDF URL貼り付けで続行できる。

## 実装

- フロントエンド: React / TypeScript / Tailwind CSS
- ビルド: `scripts/build.mjs` によるRollup + TypeScript transpile
- PWA: manifest + service worker
- PDF解析: `pdfjs-dist`
- 保存: localStorage
- proxy: `functions/api/*.ts`（Cloudflare Pages標準）/ `worker/src/index.ts`（任意の外部Worker）

## TDnet取得

2026年6月20日時点で確認した構造:

- 検索フォーム: `https://www.release.tdnet.info/onsf/TDJFSearch/TDJFSearch`
- 検索期間候補: `I_head` の `select[name='t0']`
- 検索結果行: `#maintable tr`
- 一覧HTML: `I_list_001_YYYYMMDD.html`
- 一覧行: `#main-list-table tr`

アプリではTDnet検索フォームを優先し、決算短信・決算説明資料が無い場合はJPX「東証上場会社情報サービス」の会社別開示履歴へフォールバックする。TDnet/JPXとも取得できない場合だけ日別一覧を探索し、最終的に手動PDFへ誘導する。

ユーザー設定の検索期間が120日未満でも、決算関連資料が見つからない場合はJPX履歴検索を120日まで自動拡張する。四半期サイクルの決算短信が短期設定から漏れることを防ぐためである。

JPX履歴取得は `worker/src/jpxDisclosures.ts` に集約し、Pages Functionと外部Workerで共用する。フロントエンド側の取得順序・候補統合・スコアリングは `src/lib/disclosureFetcher.ts` に集約する。

## 精度向上仕様（2026-08-09）

### 評価契約

- 実在の決算短信を元にしたゴールドケースを用意し、資料選定、主要数値、単位、期間、連結区分、予想、配当、警告、根拠ページを期待値として保持する。
- 資料選定は正解率、数値は完全一致率・単位一致率、警告はPrecision / Recall / F1、根拠ページは包含率を算出する。
- 重大項目（銘柄、資料種別、期間、連結区分、主要数値、単位）は誤り0件を合格条件とし、曖昧な場合は誤った値を確定表示せず「不確実」とする。

### 資料発見・候補選定

- TDnetとJPXをソース別に `success` / `empty` / `failed` / `truncated` で管理し、取得障害と該当なしを区別する。
- TDnetに説明資料しかない場合もJPXの決算短信を探索し、両ソースを統合して比較する。
- JPXは先頭10件固定にせず、安全な上限内でページングする。
- 自動選定は決算短信を第1優先、決算説明資料を第2優先とする。業績予想・配当資料だけの場合は自動的に決算短信成功扱いしない。
- 銘柄コード一致を必須とし、文書種別、訂正・差替、開示日時、PDF/XBRL有無、安定IDの順で決定的に選定する。
- TDnet/JPXでURLが異なる同一資料は、銘柄・正規化タイトル・開示日・書類IDで重複排除する。

### PDF・XBRL・統一facts

- PDF文字抽出は文字座標を保持し、Y座標で行、X座標で列順を復元する。抽出品質をスコア化し、表構造が曖昧な場合は主要数値の確定を抑止する。
- XBRLはcontextの期間、entity、dimension、連結候補、unitRefを解析し、context名だけで当期・前期・予想を判定しない。
- `decimals`は精度として扱い、通貨単位には使用しない。主要指標は同一contextから取得し、contextが曖昧ならPDF値を無条件に上書きしない。
- PDFとXBRLは出所、値、単位、期間、連結区分、根拠ページ、品質、警告を持つ統一factsへ正規化する。
- 判定、見出し、主要数値、良い点、注意点、Markdown、AI入力は同一factsから再生成し、XBRL採用後にPDF由来の古い結論を残さない。

### Workers AI

- AI入力は先頭固定長の本文ではなく、統一factsとページ番号付きの関連抜粋を優先して構成する。
- Workers AI JSON Modeで根拠付き構造化出力を要求し、各主張にカテゴリ、事実、ページ、根拠、不確実性を持たせる。
- AI応答は表示前にschema、ページ範囲、入力factsとの数値整合、禁止表現、免責を検証する。無効な応答は表示せず、端末内ルール要約へフォールバックする。
- 使用モデル、入力ハッシュ、検証結果を保存し、実際に送信した入力を監査可能にする。

### 実装済み精度ゲート（2026-08-11）

- `npm run accuracy` で公式PDF 1件と合成回帰5件を実行する。公式PDFはSHA-256を記録し、入力欠落時はテストを緑化せず失敗させる。
- PDF品質は文書全体と対象ページの両方を検査する。実績、予想、配当のうち曖昧なページに属するfactsだけを確定しない。
- 単位未検出、XBRL主要指標3件未満、PDF/XBRLの期間・連結区分不一致は、自動上書きを抑止する条件とする。
- XBRLは同一期末なら四半期単独値より累計durationを優先し、ZIP内では拡張子よりSummary/Attachment区分を優先する。
- AI claimsは最大8件とし、各数値を部分文字列ではなくNFKC正規化済み数値トークンの完全一致で検証する。
